Statistical Integrity over Marketing Hyperbole. An ROC-AUC of 0.786 is not 0.85; the 95% bootstrap interval is [0.72, 0.85] on 250 held-out applications, and a baseline logistic regression scores 0.778 on that same holdout. The core contribution of this system is the engineering layer above raw scoring: cost-optimal threshold calibration, additive attribution, adverse action compliance, and automated numerical grounding that rejects hallucinated LLM rationale.

1. The Threshold is the Decision Engine

Under the official German Credit asymmetric loss matrix, approving a bad loan costs 5 cost units, whereas declining a good loan costs 1 cost unit. A standard 0.50 cutoff costs more per applicant than declining every single borrower.

Bayes-Optimal Decision Rule

For probability \(p = P(Y=1 \mid x)\), the expected cost of approving is \(5p\), while the expected cost of declining is \(1(1-p)\). Equating the expected costs yields the theoretical minimum:

\[ p^* = \frac{C_{\text{FP}}}{C_{\text{FP}} + C_{\text{FN}}} = \frac{1}{1 + 5} = \frac{1}{6} \approx 16.7\% \]

Empirically calibrated over out-of-fold training probabilities, the loss-minimizing operational cutoff shifts to 21.2%, achieving expected cost \(0.584\) vs \(0.700\) for a naive policy.

4. Multi-Tiered Architecture & Grounding Verification

Four layered endpoints ensure that lending decisions never depend on LLM uptime, hallucinations, or API latency:

Endpoint Payload Output LLM Invoked Failure Mode
GET /health Model readiness and vector store status No Never (Readiness probe)
POST /score Calibrated probability & cost-optimal decision No Artifacts missing
POST /explain The above + SHAP factors & adverse action codes No Artifacts missing
POST /ask Verified conversational answer with numeric grounding Yes Provider down (graceful fallback to verified template)

Three Verification Checks on Every Answer

1. Numeric Grounding: Every single number in the LLM answer is regex-extracted and asserted against the mathematical context.

2. Citation Verification: Every case ID cited must match a record actually retrieved from ChromaDB.

3. Protected Rationale Guard: Protected attributes cannot be framed as causal rationale for declines.

Failing Answers are Replaced, Not Annotated

Showing a hallucinated answer with a disclaimer badge is how bad decisions happen. If an answer fails grounding, the service substitutes a deterministic rule-based template built from verified data and sets grounded: false.

Over 50% of the guard test suite validates that correct answers are not falsely rejected.
