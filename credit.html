3. Fairness, tested properly

The system already hid protected attributes from the officer's view and blocked the LLM from citing one as a reason. Neither is a fairness result. This measures what the model actually does to each group.

GroupnApproval rate Bad rateApproved among non-defaultersAUC

The test that was wrong

The first version bootstrapped the min/max approval-rate ratio and checked whether the interval excluded parity. It reported all three attributes as conclusively disparate — including one whose minority group has eight members.

The error: min over a set of noisy group rates is a biased estimator. With four groups of unequal size, the smallest lands at the bottom by luck alone, so the point estimate sits below the truth and a bootstrap centred on it inherits the bias intact. The four-fifths rule fires on that noise.

The test that replaced it

A permutation test. Shuffle group labels against fixed decisions and recompute the ratio: every permutation has the same group sizes and the same minimum-of-four-noisy-rates effect, so the null distribution absorbs the bias.

Result: one attribute untestable, one gap explained by realised default rates, and one real finding — the age gap survives restricting to applicants who did not default, so differing risk does not explain it.

So drop the protected attributes? Here is the price.

Refit without them, same hyperparameters, same calibration, threshold re-selected out-of-fold so the ablated model is not handicapped.

4. The LLM is not allowed to decide anything

Four endpoints, layered by how much you should trust them. A caller who wants a decision never depends on a language model being up, correct, or affordable.

EndpointReturnsLLM involvedFails when
GET /healthModel and store readinessnonever — it is the readiness probe
POST /scoreProbability and cost-based decisionnoartifacts missing
POST /explainThe above, plus SHAP factors and reason codesnoartifacts missing
POST /askThe above, plus a narrated answeryesprovider down — everything else still returns

Three checks on every answer

Numeric grounding. Every figure in the answer must appear in the supplied context.

Citation validity. Every case ID cited must be one that was actually retrieved.

Protected rationale. A protected attribute may not be framed as a reason — checked at sentence level, so mentioning age in passing is not a violation while citing it as the cause is.

A failing answer is replaced, not annotated

Showing a suspect answer with a warning attached is how warnings get ignored. The guard substitutes a safe answer built from the verified evidence and returns grounded: false so the caller knows.

Roughly half the guard's tests check the opposite direction — that correct answers are not rejected. A guard that cries wolf gets switched off.

What the guard cannot catch. A false causal claim containing no numbers, no case citations and no protected attribute — "applicants like this rarely recover once they miss a payment" — passes all three checks and is pure fabrication. Catching it needs entailment checking, which means a second model that can also be wrong, in the layer where being wrong is worst. The gap is in the model card's failure table rather than patched over.

The retrieved neighbourhood carries real signal about default — 0.61 against a chance baseline of 0.5. Blending it with the model score nonetheless makes accuracy slightly worse.

The store holds training rows the model already learned from, so the neighbours add nothing it does not know. The layer stays because its job is to make a decision explicable — "three of the five closest past applicants defaulted" is checkable by a human in a way a log-odds table is not. That is the claim made for it, and it is not a claim about accuracy.

6. Run it yourself

git clone https://github.com/nimb-ou/loan-underwriting-copilot
cd loan-underwriting-copilot
make venv
make all        # downloads data, trains, evaluates, writes the model card

make api        # http://localhost:8000/docs
make ui         # http://localhost:8501

No API key needed — the LLM layer falls back to a labelled stub. make all is incremental; it skips any stage whose inputs have not changed.
